# 局限

[English](../limits.md)

先把 QuorumVault 目前做不到的事说清楚，省得你踩坑才发现。

- **只在本地链上跑过。** 测试用的是本地 EVM 节点、Bitcoin regtest 和本地 Solana validator。没遇到过真实的手续费市场、深度重组或拥堵的网络。
- **没上过测试网或主网。** 不要把它指向真实资金或真实密钥。
- **用的是 SoftHSM，不是硬件。** 令牌是软件，没有防篡改能力。结构上是真 HSM 需要的那一套，但它不是真 HSM。
- **M-of-N 是模拟的。** 冷钱包签名机用软件检查运维人员的签名；硬件 HSM 会自己强制执行。
- **所有参与方跑在一台机器上，由同一个团队运行。** 密码学上的隔离是真的，运维上的隔离不是。
- **cb-mpc 没有在这里经过外部评审。** 所以任何密码学失败都会让密钥冻结。
- **`X-Actor` 不是认证。** 它只是给双人审批标出调用者。没有真正的身份系统，也没有界面。
- **没有压测。** 数字是在笔记本上测的，不是目标硬件。见[实测数字](../measurements)。
- **两方密钥需要两方都在。** A 或 B 宕机时，Bitcoin 和 Solana 存款的归集会暂停。
- **Bitcoin 每个池只有一个热钱包分片**，所以没有再平衡。
- **Solana 的覆盖更窄。** 只认经典的代币程序，客户数量很大时扫描方式也得换；冷钱包上用最近区块哈希签名的仪式（初始化、关闭 nonce 账户）必须在它的短寿命内完成。
- **EVM 和 Bitcoin 的每个冷钱包地址同一时间只能有一个补充申请**（Solana 是每种资产一个）；Solana 的热钱包充值由运维调用记账，不是扫描发现的。
- **恢复演练只在一台机器上做过**，没有跨机房。

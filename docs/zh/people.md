# 人员

[English](../people.md)

QuorumVault 只在规定的人都同意后才动用资金。发起付款的人不能批准自己的付款；决定"谁有权批准"的，是另一组人。

## 角色和职责

| 角色 | 职责 | 通常由谁担任 |
|:---|:---|:---|
| 发起人 | 开立客户、生成充值地址、发起提现 | 交易所的后端系统或客服人员 |
| 审批人 | 用个人密钥批准或拒绝每笔提现 | 资金或财务负责人 |
| 运营人员 | 日常操作：从冷钱包补充资金、批量付款、账本与链上对账 | 当班的运营团队 |
| 签名区管理员 | 签署签名区的设置：审批人名单、在用密钥、手续费上限 | 安全负责人 |
| 冷钱包签名人 | 在离线机器上签署冷钱包的转出 | 资深托管人员 |
| 合约管理员 | 更改充值合约的行为，很少用到 | 平台负责人 |

## 每件事需要几个人

- **提现**：按金额分档，每档至少一位审批人，金额越大，要求的人数不会减少；发起人本人不能算在内。
- **签名区设置变更**：多位签名区管理员共同签名。
- **冷钱包转出**：N 位签名人中的 M 位，在密钥仪式上完成。

一个人可以担任多个角色，但系统按人计数，不按密钥计数：同一个人的两把密钥只算一票。

示例：一家小型交易所，交易后端是发起人，两位财务负责人是审批人，三位安全负责人是签名区管理员，这三位加上财务总监是冷钱包签名人。

## 如何证明身份

- **登录**：在公司的身份提供方登录，获得核心 API 的角色；重要操作要求重新登录（[身份](identity.md)）。
- **个人密钥**：批准必须用个人密钥签名。[签名区](signing-zone.md)按自己的名单核对签名，不只依赖登录。密钥可以是硬件安全密钥，在网页或命令行工具里使用。
- **离线密钥**：用于签署签名区设置和冷钱包转出，从不接触在线系统（[冷热钱包](tiers.md)）。

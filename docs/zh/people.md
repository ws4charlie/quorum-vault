# 人员

[English](../people.md)

QuorumVault 只有在该同意的人都同意之后才会动钱。没有人能既发起一笔付款又批准它，而决定"谁有权批准"的又是另一组人。

## 谁做什么

| 谁 | 做什么 | 通常是 |
|---|---|---|
| **发起人** | 建客户和充值地址，发起提现 | 交易所自己的后端，或客服人员 |
| **审批人** | 用个人密钥批准或拒绝每一笔提现 | 资金或财务负责人；每笔付款需要两人或更多 |
| **运营** | 负责日常操作：冷钱包补充、批量付款、账本与链上对账 | 当班的运营团队 |
| **签名区运营** | 签署签名区自己的设置：谁是审批人、用哪些密钥、手续费上限 | 安全负责人；每次变更需要多人签名 |
| **冷签名人** | 在离线机器上签署冷钱包的转出 | 资深托管人员；N 人中 M 人，以仪式方式进行 |
| **管理员** | 更改充值合约的行为 | 平台负责人，很少用到 |

举个例子，一家小交易所：交易后端是发起人，两位财务负责人是审批人，三位安全负责人是签名区运营，这三位再加上财务总监是冷签名人。

## 各自如何证明身份

- **登录**：在公司的身份提供方登录，得到核心 API 的角色；重要操作需要刚刚登录过（[身份](identity.md)）。
- **个人密钥**：审批靠它生效。[签名区](signing-zone.md)用自己的名单核对签名，不只相信登录。密钥可以是硬件安全密钥。
- **离线密钥**：用来签署签名区设置和冷钱包转出，从不接触在线系统（[冷热钱包](tiers.md)）。

一个人可以有多个角色，但系统数的是人，不是密钥：同一个人的两把密钥只算一次批准。
